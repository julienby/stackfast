La boucle : hub ↔ instances ↔ apps

Un seul mécanisme de capitalisation, décliné à trois niveaux. Le hub est la seule source de vérité pour les stacks ; les instances ne font que la refléter.

La règle en clair

  1. Une erreur sur une seule app : corrigée dans apps/<stack>/<slug>/AGENTS.md, sur l'instance. Elle ne bouge plus de là.
  2. La même erreur sur deux apps : /retro te le signale, tu décides. Le fix va dans INIT/stacks/<stack>/AGENTS.md — mais pas depuis l'instance : il faut l'écrire dans un clone du hub (repo stackfast), commit, push. L'instance ne peut pas éditer stacks/ (c'est écrasé au prochain install.sh).
  3. Repropager vers les autres VPS : sur chaque instance (A, B, C…), relancer sh INIT/install.sh . (ou le one-liner curl … | sh). Ça clone le hub à jour, écrase stacks/<stack>/ localement, laisse apps/ intact. Tu commites ensuite ce changement dans le repo de l'instance.
  4. Erreur qui traverse deux stacks : même logique, un niveau au-dessus — elle va dans ~/.claude/CLAUDE.md (édité directement, ou via INIT/CLAUDE.global.md du hub puis install.sh qui le repose sur chaque machine).

Point de friction actuel : l'étape 2 est manuelle (pas de script qui édite le hub depuis une instance) — c'est voulu, ça force une relecture avant que la règle devienne globale à toutes les apps de la stack.
