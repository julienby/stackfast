jbh : mode d'emploi

jbh range les fichiers qui règlent ton assistant IA. Tu les écris une fois. Tu les reprends dans chaque projet.

1. L'idée en une minute

Ton assistant IA lit des fichiers texte pour savoir comment travailler avec toi. Ce sont des fichiers .md : des consignes, des compétences.

Sans jbh, ces fichiers sont copiés à la main d'un projet à l'autre. Ils se perdent. Ils divergent. Tu ne sais plus lequel est le bon.

Avec jbh, il existe une seule source. Chaque projet prend sa copie depuis cette source. Quand la source change, tu mets à jour la copie.

jbhla source, avec l'historique de chaque version
→
Ton poste~/.claude et ~/.codex
+
Tes projetsAGENTS.md et .claude/skills/

L'IA ne parle jamais à jbh. L'IA lit des fichiers locaux, comme d'habitude. jbh, lui, met ces fichiers à jour. Ainsi, tu peux changer de fournisseur d'IA sans perdre tes réglages.

2. Les mots à connaître

MotSens
RessourceUn élément rangé dans jbh. Elle a un type et un nom, par exemple skill/explain.
instructions-mdUn type. C'est un fichier de consignes : AGENTS.md ou CLAUDE.md.
skillUn type. C'est un dossier avec un SKILL.md et d'autres fichiers si besoin.
VersionChaque envoi crée une nouvelle version : v1, v2, v3. Les anciennes restent. Rien ne se perd.
JetonTon mot de passe pour jbh. Sans lui, personne ne lit rien.
.jbhUn petit fichier à la racine d'un projet. Il note ce que le projet a pris dans jbh, et à quelle version.
FusionMélanger tes changements locaux et les changements de jbh, sans rien écraser.

3. Démarrer

jbh a deux parties : un serveur (l'API) et un client (la commande jbh).

Ce qu'il te faut

  • sh, curl et jq pour le client. Pour jq : sudo apt install jq.
  • diff3 pour la fusion. Il vient avec diffutils, déjà présent sur la plupart des systèmes.
  • PHP 8.3 avec pdo_sqlite, seulement pour lancer le serveur toi-même.

Lancer un serveur local pour essayer

Le déploiement sur jbh.byjulien.com n'est pas encore fait. En attendant, lance le serveur sur ta machine. Dans le dossier du repo :

export JBH_TOKEN="un-mot-de-passe-long-que-tu-choisis"
export JBH_DB="$HOME/.local/share/jbh.sqlite"
php -S 127.0.0.1:8080 app/index.php

Laisse ce terminal ouvert. Le serveur tourne tant qu'il reste ouvert.

Régler le client

Dans un autre terminal :

export JBH_TOKEN="un-mot-de-passe-long-que-tu-choisis"
export JBH_URL="http://127.0.0.1:8080"
export PATH="$PWD/bin:$PATH"

jbh list

Si la liste est vide et sans erreur, tout fonctionne.

Le jeton doit être le même des deux côtés. Ne l'écris pas dans un fichier que tu publies. Ne le mets pas dans Git.

4. Stocker un fichier

Exemple : tu as un fichier de consignes pour tes projets PHP.

  1. Écris le fichier

    Crée php.md avec quelques lignes de consignes.

  2. Envoie-le 
    jbh update instructions-md web-php --with php.md
instructions-md/web-php v1

    Lis la commande à voix haute : « mets à jour la ressource de type instructions-md qui s'appelle web-php, avec ce fichier ».

  3. Vérifie 
    jbh list
instructions-md web-php v1
  4. Modifie, puis renvoie

    Change php.md. Relance la même commande update. La ressource passe en v2. La v1 reste dans l'historique.

Un skill est un dossier

jbh update skill explain --with ./explain/

Tous les fichiers du dossier partent ensemble. Ils forment une seule version.

Les autres commandes de base

CommandeEffet
jbh list [type]Montre les ressources, avec leur dernière version.
jbh get <type> <nom> [--to dossier]Lit une ressource. Avec --to, écrit les fichiers dans ce dossier.
jbh update <type> <nom> --with <fichier|dossier>Crée ou met à jour. Chaque appel ajoute une version.
jbh delete <type> <nom>Supprime la ressource et tout son historique.

delete ne se rattrape pas. L'historique part avec la ressource.

5. Régler ton poste : pull

Ton poste a des réglages pour tous tes projets : ton CLAUDE.md global et tes skills personnels. pull les installe.

jbh pull

La commande écrit dans ~/.claude/ et ~/.codex/. Elle prend tous les skills et la ressource instructions-md/global. Ensuite, elle n'a plus besoin du réseau : l'IA lit les fichiers locaux.

Avant d'écraser un fichier, pull en garde une copie dans ~/.config/jbh/sauvegardes/. Tu peux donc toujours revenir en arrière.

6. Utiliser dans un projet

pull règle ton poste. Pour un projet précis, tu choisis ce qu'il prend. Place-toi à la racine du projet.

  1. Ajoute une ressource 
    cd mon-projet
jbh add instructions-md web-php
ajouté : instructions-md/web-php v1 → AGENTS.md

    jbh écrit AGENTS.md. Il crée aussi un CLAUDE.md qui contient @AGENTS.md. Claude et Codex lisent ainsi le même texte.

  2. Ajoute un skill 
    jbh add skill explain
ajouté : skill/explain v1 → .claude/skills/explain
  3. Choisis un autre emplacement si besoin 
    jbh add instructions-md api --to app/AGENTS.md

    Utile quand une partie du projet a ses propres consignes, par exemple le dossier app/.

  4. Regarde l'état 
    jbh status
instructions-md/web-php v1 à jour
skill/explain v1 → v2

    Le sens des lignes est dans le tableau plus bas.

  5. Mets à jour 
    jbh sync
  6. Retire une ressource 
    jbh remove skill explain

Lire jbh status

LigneSens
… v1 à jourTu as la dernière version. Rien à faire.
… v1 → v2jbh a une version plus récente. Lance jbh sync.
… v1 (modifié en local)Tu as changé le fichier dans le projet. jbh ne le touchera pas sans fusion.
… v1 → v2 (modifié en local)Les deux ont changé. sync fusionnera.
… v1 absent de jbhLa ressource a été supprimée dans jbh.

Le fichier .jbh

Il vit à la racine du projet. Il contient une ligne par ressource : type, nom, version, destination.

instructions-md web-php 2 AGENTS.md
skill explain 1 .claude/skills/explain

Mets .jbh dans Git. Ainsi, toute l'équipe voit quelles versions le projet utilise. Lance les commandes jbh depuis la racine : jbh ne cherche pas .jbh dans les dossiers parents.

7. Quand local et distant diffèrent

C'est le cas qui fait peur : tu as ajouté une ligne utile dans le projet, et jbh a une nouvelle version. Qui gagne ?

Personne ne gagne : jbh fusionne. Il compare trois textes :

  • la base : la version que tu avais prise au départ (jbh la garde) ;
  • le local : ton fichier actuel ;
  • le distant : la nouvelle version de jbh.

Exemple pas à pas

La base contient cinq lignes : un deux trois quatre cinq.

  • Dans ton projet, tu changes la ligne 1 en un local.
  • Dans jbh, tu changes la ligne 5 en cinq distant.
jbh sync
fusionné : AGENTS.md

Résultat : un local deux trois quatre cinq distant. Les deux changements sont là. Ils ne touchaient pas la même ligne.

Quand les deux touchent la même ligne

jbh ne peut pas deviner. Il garde ton texte et marque le problème :

jbh sync
CONFLIT : AGENTS.md
<<<<<<< local
un local
||||||| base
un
=======
un distant
>>>>>>> jbh

Ouvre le fichier. Garde ce que tu veux. Supprime les trois lignes de marqueurs. Enregistre. C'est fini.

Même avec un conflit, .jbh passe à la nouvelle version. La prochaine fusion partira donc de la bonne base. La commande se termine avec une erreur, pour te prévenir.

Les règles, en bref

  • Tu n'as pas touché au fichier → jbh le remplace par la nouvelle version.
  • Tu as supprimé un fichier sans l'avoir modifié → jbh ne le remet pas.
  • jbh a retiré un fichier d'un skill → il le supprime chez toi, seulement si tu ne l'as pas modifié.
  • Tu as ajouté un fichier à toi dans un dossier de skill → jbh n'y touche jamais.

8. La page web

La page web sert à lire. Elle ne modifie rien.

  1. Ouvre l'adresse du serveur dans ton navigateur, par exemple http://127.0.0.1:8080/.
  2. La page demande ton jeton. Colle-le, puis valide.
  3. Tu vois la liste des ressources. Clique sur l'une d'elles pour voir son contenu.
  4. Dans le détail, clique sur « historique » pour voir toutes les versions, de la plus récente à la plus ancienne. Clique sur une version pour la relire.
  5. « Quitter » efface le jeton du navigateur.

Le jeton reste dans l'onglet seulement. Si tu fermes l'onglet, tu dois le saisir à nouveau. C'est voulu : rien ne traîne sur ta machine.

10. Si ça ne marche pas

MessageCause et remède
JBH_TOKEN est videTu n'as pas exporté le jeton dans ce terminal. Relance export JBH_TOKEN=….
le serveur ne répond pasLe serveur est éteint, ou JBH_URL est faux. Vérifie le terminal du serveur.
erreur 401Le jeton du client diffère de celui du serveur. Compare les deux.
erreur 404 : item inconnu ou introuvableLe type ou le nom est faux. Regarde jbh list.
pas de fichier .jbh iciTu n'es pas à la racine du projet, ou tu n'as jamais lancé jbh add.
des conflits restentCherche <<<<<<< dans tes fichiers, puis règle chaque cas (voir la partie 7).

Le nom d'une ressource ne contient que des lettres, des chiffres, le point, le tiret et le souligné. Il commence par une lettre ou un chiffre.
